## ① 竖直圆柱 + 上部斜切 + 左侧竖直台阶

最初的题，当时还没有 skill，靠临时脚本硬做出来的 —— 后来整套工具的骨架就是这么长出来的。

**形体**：竖直圆柱 `R=1`、`H=2.09R`。上部被一个斜面切掉，左侧还留了一个竖直台阶，中段只剩右侧一片薄壁。

- 台阶面 `x = 0.609R`，`z ∈ [0.18H, 0.449H]`
- 斜切面从 `z=0.449H` 升到 `z=0.888H`，同时 `x` 从 `0.609R` 退到 `−R`（倾角约 30°）

**怎么校验**：左视图那条椭圆弧是斜切面与柱面的交线，它的半轴比 0.55 应当接近斜面斜率 0.57 —— 两条独立数据互相印证，形体就锁死了。俯视图那条竖直虚线是台阶面，被上方圆柱挡住所以画成虚线；而外轮廓仍是完整圆，说明没有被削掉一整层。

**踩的坑**：

1. `THREE.EdgesGeometry` 配合未合并顶点，会把每条三角形边都当轮廓，画成一片网格。最终干脆手绘特征棱线。
2. `flatShading: true` 配合扭曲四边形会产生明暗条纹，误看成多余网格线。
3. 切口朝左下，标准轴测（右前上方）完全看不见，必须给「仰视」视角 —— 这条后来升级成硬规则。
4. 浏览器截图通道偶发 `display surface not available`，改用 Python 光线投射离线自查机位。

> 这一题的交付 HTML 是唯一还停留在 CDN 版本的文件（12 KB），其余 8 题都已重打包成引擎内联的离线版。

## ② 视觉外壳首测（模式 A 的由来）

同一个思路换个方向：既然三视图各自是一个实心区域，那三维形体就是三个掩码的**交集**：

```
V(x,y,z) = F(x,y) ∧ T(x,z) ∧ L(z,y)
```

主视图掩码沿 z 拉伸、俯视图沿 y 拉伸、左视图沿 x 拉伸，三者相交即是"满足三视图的最大形体"。投影手性（第一角/第三角）有 4 种翻转组合，自动择优。

一条命令 3.5 秒出页面，从此不用人工反推形体。代价写在图里了：**曲面被台阶化**，内部空腔被填平，也不画棱线。

**踩的坑**（这题连撞三个真 bug）：

1. `PIL.resize` 尺寸写成了 `(nx, ny)` 又转置 —— 三张掩码被**同时**转置 90°，吻合度照样 0.978。这是个自洽的假阳性，只能靠"上排贴原图"兜底。
2. 视图内部的贯通实线把实心区切成两块，与图外白区连通，`fill_holes` 抓不到 → 模型裂成四块。加形态学闭运算 `n=2` 后，吻合度 0.9596 → **0.9945**。
3. 初版 4.9 MB / 10824 面片。共享顶点 + 跨行合并 + 紧凑序列化后 **45.7 KB / 446 面片**。

## ③ 圆柱 + 贯通三角孔

**形体**：`R=1`、`H=2.32R` 的圆柱，沿 z 贯通一个三角孔。

- 侧平面 `x = −0.678R`（孔的左壁）
- 水平面 `y = 0.830H`（孔顶）
- 正垂面 `y = 0.088H + 1.116(x − X₁)`（孔底斜壁，与柱面交出椭圆）

**踩的坑**：手写面片时有 **998/1178 个三角形绕向与顶点法线相反**。材质是 `DoubleSide`，页面照样能看，但 GPU 按背面翻转法线 —— **明暗整体是反的**，而且看不出来。

抓法是用散度定理算有符号体积：初测 **−3.12**，解析值 4.86。修法是逐面按 `dot(面法线, 顶点法线)` 纠正，再按全局体积符号定向。修后 4.8607，误差 0.038%。

另一个坑：模板默认机位在左前上方，被左侧柱壁挡住，完全看不到孔 —— 改成右前方中等高度。

> 这题之后才有 `check_mesh.js`（体积/边界边/绕向/退化面自检）和模板的绕向自愈。

## ④ 圆筒 + 竖直凸台 + 竖直通孔

**形体**：竖直凸台（φ1.66）立在水平圆筒（φ2，长 2.742）上，轴线右移 0.541 —— 恰好 `X₀ + RBOSS = L`，凸台与右端面相切。竖孔 φ1.044 从凸台顶面贯通到筒底，途中穿过水平内孔 φ0.684。

三处相贯：①凸台∩筒面 ②竖孔∩筒面（筒底开口）③竖孔∩内孔。

**做法**：没有用模式 A，把布尔差列成 **7 张曲面清单**，每片用一张参数网格铺，边界就是解析交线：

- 筒外圆面 → 绕竖直轴的极坐标环带（内圈是足迹圆，外圈是矩形边界）
- 凸台侧面 → 波底带（底边是相贯线 `y = √(R² − r²sin²θ)`，顶边是圆）
- 竖孔壁 / 内孔壁 → 两带法（被切处拆成上带/下带，pinch 处自然闭合）

**验证**：有符号体积 7.0725，Richardson 外推体素值 7.0753，差 0.05%；12768 个三角形，绕向异常 0，边界边只出现在分片接缝；反投影三个视图全部压在描边中线上（误差 ~1 px）。

> 这题之后才有 `project_mesh.py`。旧的 `verify_projection.py` 是"两边各自拉伸后比"，整体偏移会被抵消 —— 交付前的底线校验不能这么松。

## ⑤ 支架：斜面台阶 + 半圆凸台 + 倒梯形槽

**形体**：主视图是五边形 → 主体是「沿深度方向拉伸的五边形板」。右上方立半圆凸台 `R=9.70`（圆心在顶面高度、深度中点），凸台与孔轴线沿**长度方向**贯通至左端面。顶面开一条倒梯形槽，沿长度开通，左端被斜面截断。

| 参数 | 值 | 参数 | 值 |
|---|---|---|---|
| 长 `W` | 27.6 | 槽深到 `ZF` | 7.20 |
| 深 `D` | 25.7 | 槽口半宽 `GA` | 7.55 |
| 顶面高 `Z1` | 14.15 | 槽底半宽 `GB` | 4.40 |
| 凸台半径 `RB` | 9.70 | 孔径 `RH` | 4.30 |

**线条对应**（反投影时逐条对上的）：

| 图上线条 | 含义 |
|---|---|
| 主视虚线 y=100 / 186 | 通孔上下素线（孔被前方材料遮挡） |
| 主视虚线 y=213 + 竖虚线 x=266 | 槽底平面 + 槽左端壁（被斜面截断处） |
| 左视外弧 R=97.77 px / 内圆 R=43 px | 凸台半径 9.70 / 通孔半径 4.30 |
| 俯视斜线斜率 0.541 | 槽壁斜率 `(GA−GB)/槽深 = 3.15/5.95` |

**踩的坑**：

1. **顶面被写成一个 12 边形** → 耳切算法直接从槽口上方跨过去，产生穿模三角形，体积偏 **5.2%**，报 `earClip 未收敛，剩余 4 点`。改成槽口左右**两条独立条带**后降到 0.076%。凡是"面中间被挖掉一块"，不能靠单个凹多边形硬啃。
2. **模型片段顶层 `const D` 与模板的 `const D` 重名** → 整个 ES module 解析失败，页面只显示"渲染引擎加载失败"，而文件本身完全合法。模型必须包进 IIFE，内部用 `DP` / `HT` 这类前缀名。
3. 模板 `#hint` 漏了 `position: fixed`，变成普通块元素，占掉顶部 30 px 把 canvas 压下去。

**验证**：894 个三角形，有符号体积 8401.37，误差 0.076%；三视反投影红线全部压在描边上。

> 这题 27 分钟里脚本只占约 15 秒，其余全是"写临时脚本 → 看图 → 再写"。所以下一步不是优化脚本，是**减少往返**：`measure.py`、`shot.py`、`pipeline.py` 三个脚本就是为这个加的。

## ⑥ 选择题：槽口算不算外轮廓（A / B 二选一）

给主视图 + 俯视图，在 (A)、(B) 里选正确的左视图。

**形体**：方块 165×131×114（长×高×深），顶面一条沿**深度方向**的倒梯形槽（槽口 x=29.5..134.5、槽底 x=50.5..114.5、槽底高 85.5），前面被两刀切掉楔形：

- 竖直斜切面 V：`z = 99 − 0.5x`（俯视图那条对角线就是它的水平迹线）
- 斜台阶面 S：`y = 19.75 + 0.30x`
- 两面交线 `(0, 19.75, 99) → (165, 69.25, 16.5)`，正好同时是三张图里那条斜线

**判据**（这题最有价值的一条）：俯视图里槽的 **4 条竖线（两对槽壁）都终止在同一条斜线上**。槽壁在 `x=const` 的竖直面上，只有被**竖直面**切，才能让上下两条槽底/槽口棱在同一列像素同时结束 —— 据此唯一确定 V 是竖直面，而不是一般斜面。

**判决**：把"左视图"分别指向 A、B 各跑一次反投影，统计每条投影线有多少长度在原图上找不到线：

| 选项 | 落线率 | 最长悬空段 | 结论 |
|---|---|---|---|
| A | 93.24% | **49 px**（正在槽口上方的顶边） | 把槽口画成了外轮廓缺口 |
| B | 99.37% | 3 px（抗锯齿噪声） | 正确 |

命中率 93 与 99 肉眼分不出来，**最长悬空段**才是判决性的。

**踩的坑**（两个都是工具链的真 bug）：

1. `project_mesh.py` 的 `--boxes` 只用于标签位置，**没传进 auto_calib**，仍按默认三等分切框 → 选择题拼图得到 `S=1.6754`、离散度 71.75%、命中率 20.8%。修好后 `S=1.0000`、离散度 3.5%、命中率 100%。
2. `MODEL.views` 的值必须是**相机位置数组** `[x,y,z]`（注视点固定为 `MODEL.center`）。写成 `{pos, target}` 会让模板 `new Vector3(...views.iso)` 抛 `Spread syntax requires ...iterable`，整页白屏。`shot.py` 的探针直接把这一行错误抓出来，省掉了"截图看不见 → 猜是 CDN → 猜是语法"的两轮往返。

## ⑦ 圆柱 + 后部圆冠凸台 + 前上方斜切平台

**形体** = 圆柱 ∩ 高度上限 `h(z)`：

```
h(z) = 285              z ≤ 56          （凸台，圆冠）
     = 220 − 0.777(z−56) 56 < z ≤ 195    （斜台，斜率 108/139 ≈ 38°）
     = 112              z > 195         （前平台）
```

**怎么解出来的**：俯视图是**完整圆** + 两条水平弦 → 主体是竖立圆柱，弦是"垂直于 z 的平面"的边界。决定性的一步是把两处独立数据对上：俯视两条弦的 z 位置（58 / 198）对应左视图的两个转折（56 / 195），再核对弦长 228 / 246 ≈ 圆在该 z 处的弦长 218 / 248 —— 三组数据同时吻合，形体锁死。

**建模**：工具包没有"圆柱"，但圆柱本身就是凸体，用 N 个侧平面（内接正多边形）当半空间就行：

```js
for (let i = 0; i < N; i++) {
  const a = i * step + half, c = Math.cos(a), s = Math.sin(a);
  SIDE.push([c, 0, s, CX * c + CZ * s + R * Math.cos(half)]);   // 边心距 R·cos(π/N)
}
```

再按 z 平面切成四块：`A: z≥195` / `B: 56≤z≤195 被斜面切` / `C1: z≤56 柱身` / `C2: z≤56 凸台 221..285`。

**踩的坑**：

1. **半空间方向写反**：`zGE56` 和 `zLE195` 一开始都写成了下界，块 B 变成 `z ≥ 195`，体积少 40%。切块时逐条念"上界取正号、下界取负号"。
2. **内面剔除按三角形判 → 大三角形跨接缝会被整块删**。块 C 的 z=56 面是一个跨 y=221 的大三角形，重心落在下半截，而凸台前面那段本该保留 → 体积少 2.7%。修法是把块切到"每个面整露或整埋"，于是 C 拆成 C1 + C2。
3. `project_mesh.py` 的手性原点公式错了（`t[1] + S*z1m` 应为 `t[1] − S*z0m`），这两种手性永远评低分，`auto_calib` 只能反复选同一种。修好后命中率 79.8% → 87.4%。
4. **俯视图是圆时 top 手性不可分辨**：四种组合 `tl 76.1 / tL 86.5 / Tl 77.0 / TL 87.4`，上下翻转只差 0.9%（圆对称）。加消歧规则：两种手性差 < 2% 时按第一角画法取正向。
5. 棱线在曲面上断成点线（`LineSegments` 与多边形逼近的面片深度打架）→ 给材质加 `polygonOffset`。

**尺寸取法**：一开始按**描边外沿**取（D=274、H=286），离散度 2.61%；改成按**描边中线框**取（D=268、H=285），离散度降到 1.49%。三视图量尺寸一律用中线框。

**验证**：体积 9681454 / 解析 9685605 = 0.043%（128 边形逼近圆的残差），边界边 0，反投影命中率 86.5%。

## ⑧ 选择题：四个左视图挑一个（选 A）

外形 67×60×54 的矩形块，顶面是单值高度场，分 8 片：

| 片 | 范围 | 高度 |
|---|---|---|
| A | x 0..21, z 0..15.5 | 45° 倒角 34→54（脊在 x=21） |
| B | x 21..45.5, z 0..15.5 | 54 |
| C | x 0..45.5, z 15.5..44.5 | 浅坡 17→26 |
| D | x 0..22, z 44.5..60 | 浅坡（续 C） |
| E | x 22..45.5, z 44.5..60 | 升坡 38→54 |
| F | x 45.5..67, z 38..60 | 54 |
| G | x 45.5..67, z 22..38 | **42（凹槽底，槽口开向 +X 右端面）** |
| H | x 45.5..67, z 0..22 | 54 |

**槽口朝哪边？** 主视图里槽底 y=42 和槽后壁画的是**虚线** —— 说明槽被前面的整块材料挡住，所以它不能朝前开口，只能朝右端面开。

**这题真正的坑：拼块必错。** 先按 8 片 hull 拼，逐块 `vol()` 都对，合计正好 152024.2。但 `finish` 之后体积 **+1.640%**、边界边 24、`culled` 35。原因是槽的两侧壁**一半埋、一半露**，而内面剔除只按整三角形判 —— 邻居矮一截就必然删错。用两块相邻棱柱做最小复现：`culled 4`，体积 43258 vs 39990（+8.2%）。

改法是铺 25 个显式面片（6 顶面 + 底面 + 9 外壁 + 9 内部立面），配 Newell 公式自动纠绕向，一次通过：0.000%、边界边 0、56 个三角形。

**判选项**：dump 网格棱线 → 投影到左视图 `(u=z, v=y)` → 射线判可见 → 与四个选项逐线比。差别只有三处：

- `v=21.4` 那条横线**只出现在右侧**（深度 44.5–60，前段升坡与台阶的交线）—— B 画到了左侧，C、D 干脆没画；
- `u=15.5` 的竖线**止于 v=17**（浅坡最低边）—— B 一路拉到底；
- `u=44.5` 的竖线**止于 v=21.4** —— C 多画到 v=17，D 只画到 v=26。

A 全对（±1 px）。

## ⑨ 补画漏线：V 形槽 + 前倾顶面 + 后端方槽

外形 156(X) × 104(Z) × 92(Y)，顶面是单值高度场 **`h(x,z) = min(G(x), C(z))`**：

- `G(x)`：沿深度通长的 V 形槽横剖 —— 平顶 92（x<19）、斜壁 92→32（x 19..56）、槽底 32（56..100）、斜壁 32→92（100..137）、平顶 92（137..156）。坡度 60/37。
- `C(z)`：顶面前倾 —— `z ≤ 42` 时为 92，之后降到前脸只剩 56。
- 后端方槽：x 31.33..124.67、z 0..18，**从底面一直通到顶**。

**三个关键判读**：

1. 俯视图中段那两条竖线（x=56 / 100，z 18..104）是**槽底的两条棱**。它们在主视图里投影成点，所以主视图那个位置什么都没有 —— 这正说明槽底是水平的。
2. 主视图两条虚线只到 **y=72**。72 不是量出来的，是"V 形槽斜壁走到 x=31.33 时的高度"，也正好是后端方槽宽度的一半 → 槽壁顶边与斜壁严丝合缝，虚线干净地收在斜线上。
3. 俯视图那两条斜线是**斜壁与前倾面的交线**：`x = 19 + (0.5806/1.6216)(z−42)`，z=42 时 19、z=104 时 41.2。有了前倾顶面，V 形槽的开口边在俯视图里必然从直线变成斜线。

**拆块**：按 `G` 的折点分 5 条 x 带，再按槽的 z 范围切成前后两段，**段界 x=31.33 / 124.67 也要插进每条 x 带中间**，共 11 块。相邻块的面严格一一重合，`finish` 剔内面才精确。一次通过：`culled 56`、边界边 0、体积 856723.2（0.000%）、100 个三角形。

**漏线结论**：主视图 2 条（后端方槽两侧壁，从底拉到 y=72），俯视图 6 条（槽口两竖线、两斜线、两段短横线），左视图本来就完整 —— 共 8 条，与手写答案完全一致。

**顺带说个算体积的翻车**：列积分公式时把 `∫[zs,104] c(z)dz` 写成了 `92(104−zs) − M2(104−zs)²/2`，那是把下限当成了 z=42。正确写法是 `92(104−zs) − M2[(62)² − (zs−42)²]/2`。二维网格验算一次（差 1.7%）就能抓出来 —— 凡自造积分公式，都用数值积分独立核一遍。
