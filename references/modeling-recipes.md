# 几何建模配方与渲染经验

页面外壳由 `assets/viewer_template.html` 提供，几何由 `model.js` 提供。本文定义两者之间的契约，并收录已验证的建模手法。**不要重写渲染框架。**

## 0. 先看这里：用工具包声明几何（1 分钟）

`assets/model_kit.js` 由 `build_viewer.py` 自动注入页面（`check_mesh.js` / `project_mesh.py` 也会自动拼在前面），模型文件里一行取用：

```js
const MODEL = (function () {
  const { hull, subtract, sector, plate, fan, finish } = __KIT;
  const cells = [ /* 若干 hull / subtract 块，或一个装满面清单的 Solid */ ];
  return finish(cells);          // 直接得到满足第 1 节契约的 MODEL
})();
```

| 调用 | 语义 | 用法要点 |
|---|---|---|
| `hull(planes, {hl, skip, hlAll})` | 半空间交集 `n·p ≤ d` | `planes` 是 `[nx,ny,nz,d]`；`hl` 里的平面产出暖色面；`skip` 排除某面（换成 plate/fan） |
| `subtract(base, cuts, {hl})` | 凸体削掉一组半空间的交集 | `cuts` 写**被削掉的那一侧**；自动拆成 `2^k−1` 块，天生「拆彻底」 |
| `box(x0,x1,y0,y1,z0,z1)` | 轴对齐长方体 | 等价于 6 个半空间，读起来更短 |
| `extrude(profile, axis, a, b)` | 等截面拉伸 | `profile` 是截面点列 `[[u,v],...]`；`axis` ∈ `'x'/'y'/'z'`，截面轴映射见下 |
| `sector({axis,c1,c2,rIn,rOut,w0,w1,a0,a1,seg,cap0,cap1,hl,inward,wall})` | 圆柱/半圆/圆管/扇环 | `inward:true` 只出朝里的壁（孔壁）；`wall:true` 出外壁+内壁、不封端不出径向面；`rIn>0` 自动成管 |
| `plate({axis,w,u0,u1,v0,v1,hole:{u,v,r},seg,flip,hl})` | 带圆孔的矩形面 | 孔必须**完全在矩形内** |
| `fan({axis,w,c,r,a0,a1,seg,outer,flip,hl})` | 扇形面（孔心在面的边上） | `outer` 是函数 `θ→[u,v]` 或点列（射线求交）；必须在 `a0..a1` 上连续 |
| `finish(list, {angle,noEdges,openEdges,edges})` | 合并 + 定向 + 剔内面 + 提棱线 | `angle` 默认 25°；返回 `{positions,normals,indices,hl,edges,center,radius,size,meshes}` |

**绕向约定**：`hull`/`box`/`extrude`/闭合的 `sector` 自动朝外；`plate`/`fan` 默认法线朝 `+axis`
（`flip:true` 反过来）；`sector` 的 `wall`/`inward` 只出壁，标记为 `open`，`finish` 不会去翻它们
（开放曲面的有符号体积没有意义，翻就是错）。

**半空间语义**：`[nx,ny,nz,d]` ⟺ `n·p ≤ d`。`x ≤ 27` → `[1,0,0,27]`；`z ≥ 0` → `[0,0,-1,0]`；斜切面 `z ≤ 99−0.5x` → `[0.4472,0,0.8944,88.54]`（法线归一化，`d` 同除）。写反一条就整块消失或体积翻倍，而页面照样渲染、不报错 —— 一定要用 `check_mesh --expect` 兜住。

**`sector` / `extrude` 的轴映射**（截面内两轴，别记反）：

| `axis` | 截面两轴 | `c1` 对应 | `c2` 对应 |
|---|---|---|---|
| `'z'` | (x, y) | x | y |
| `'y'` | (x, z) | x | z |
| `'x'` | (y, z) | y | z |

`'y'` 与 `'x'` 的截面是左手系，**最容易把绕向写反**；`finish` 会对闭合体做「有符号体积为负则整体翻转」的自愈，但拼成并集后单块可能不再闭合，所以仍要看 `check_mesh` 的体积。

**`finish` 做的四件事**（手册里不用再手写）：

1. 逐块看有符号体积，负则整块翻转（并同步取反法线）；
2. 按 `pure` 标记剔内面 —— `hull` 产出 `pure=true`，被 `plate/sector` 拼过的块自动 `pure=false`（孔壁法线朝里，平面已不能描述实体，不能剔）；
3. 按二面角（默认 25°）分组法线，自动提出真实棱线，`dot≈−1` 的内部接缝与单面相邻的开放边默认不画；
4. 按 `hl` 把三角形拆成「普通 + 暖色」两个 mesh，共享同一份 `positions/normals`。

**并集要「拆彻底」**：每块都必须被所有与它相交的平面切过。少切一刀，那个面就一半露在外表面、一半埋在邻块里 —— 剔内面只能整块删或整块留，于是接缝假线爬上可见面、体积同时算错。第 6 题手写时漏一刀，体积 +14.548%。**现在交给 `subtract`**：它按每个切割平面的正反组合切成 `2^k−1` 块，拆得天然彻底（Q6 实测与手写 7 块得到**完全相同**的 40 条棱线、56 个三角形、同一个中心）。

**内面剔除的容差必须远小于挪动量**：判据是"重心沿外法线挪 `delta` 后是否落进任一 `pure` 块内部"。若平面容差取到 `delta` 量级，面会被自己所在的那张平面判成"埋在里面"而整片消失。工具包取 `delta = diag*2e-3`、包围判定 `eps = diag*1e-7`。

**棱线要做 T 形接点修补**：大面的边会被邻面多个小面顶点切成几段，只按"顶点对"建索引会丢掉真实棱（第 6 题丢过 `0,19.8,99 → 165,69.3,16.5`）。`finish` 已先按落在边上的顶点切段再建表，所以棱线条数可能多于图纸上数出来的 —— 正常。

## 0.1 两类形体，写法完全不同

判断错了会白绕一大圈，所以写在动笔之前：

| | 凸体拼合型 | 面清单型 |
|---|---|---|
| 长相 | 方块被几刀切、开槽、台阶、楔形 | 曲面体：凸台、通孔、相贯线、被孔打断的端面 |
| 写法 | `hull`/`subtract` 拼若干凸块 → `finish` 剔内面 + 提棱线 | 一个 `Solid` 里逐个 `face()` 列表面，曲面用 `sector`/`plate`/`fan` 补 |
| 为什么 | 面全在平面上，剔内面能自动清接缝 | 有曲面时平面判据失效（`pure=false`），必须只画真表面 |
| 例子 | 第 6 题（起手模板 79 行） | 第 5 题（凸台 + 通孔 + 梯形槽，60 行） |

面清单型的三条纪律：

1. **只列真实表面。** 通孔的孔壁要画（它是实体的内表面）；凸台底面压在顶面上是内部面，不画 —— 画了就会看见一片横在孔中间的板。
2. **`sector`/`fan` 的顶点数要和相邻面对齐**（半圈 64 段 ↔ 整圈 128 段），否则孔口出锯齿。
3. **端面被圆挖掉一块时，先看孔心在哪**：孔完全在面内 → `plate`；孔心落在面的边上 → `fan`。

### fan：孔心落在面的边上

`plate` 用"孔的外接方框切网格"，方框越界就失效。`fan` 改成从孔心放射：内圈是孔口圆弧，
外圈由 `outer` 给出，逐角度铺四边形。

```js
// 矩形端面 x=W 减一个整圆（下半圈打到矩形边界）
fan({ axis:'x', w:W, c:[Z1, YC], r:RH, a0:Math.PI/2, a1:Math.PI*1.5, seg:64,
      outer:[[0,0],[0,DP],[Z1,DP],[Z1,0]] })
```

`outer` 给点列时按射线求交取最近命中（自动处理角点），给函数时直接算。

**坑：`outer` 必须在 `a0..a1` 上连续。**「房子」形端面（矩形 + 凸台半圆）从孔心看，
上半圈边界在圆弧上、下半圈在矩形上，`θ=±π/2` 处会从 `RB` 跳到 `DP/2` 那种量级 ——
一个 fan 混两种边界，交界处会多出一大块细长面片（第 5 题实测体积 +0.16%）。
按 `θ=±π/2` 拆成两个 fan，上半给圆弧、下半给矩形，合起来面积精确到 0.01%。

**坑：四边形顺序是 `内a → 外a → 外b → 内b`。** 沿外圈是倒着走的，写成
`内a → 内b → 外b → 外a` 会让整块面朝 `-axis`（第 5 题三个端面全反，体积 2250 vs 8395）。

### 被凸台"占住"的那块顶面不能画

凸台坐在顶面上时，顶面在凸台足迹范围内是内部面。但更隐蔽的是：如果孔轴正好在顶面高度上，
顶面上会有一条**横穿通孔的窄条**（孔在 `y=Z1` 处的直径带），从孔口看进去正好一片板把洞挡住。
所以顶面要按「槽口 + 凸台足迹」切成两条带（第 5 题），不是一整块矩形。

**实测收益**（2026-11-10）：第 6 题手写 180 行 → 起手模板 79 行（含注释），体积
1367973.8333 相对误差 **0.000%**，棱线逐条相同；第 5 题手写 294 行 → 60 行，
体积 8394.66 vs 解析 8394.93（**0.003%**，旧手写版 0.077%），反投影落位 99.3%、比例离散度 0.63%。

## 1. MODEL 契约

`model.js` 是普通 JS 片段，可自由写函数、循环、常量；末尾必须定义：

```js
const MODEL = {
  center: [0, H/2, 0],        // 相机注视点
  radius: 1.48,                // 包围球半径；模板算视距 D = 4.2 * radius
  views: { ... },              // 可选，覆盖自动生成的机位
  meshes: [
    { positions: [x,y,z, ...], indices: [i,j,k, ...], highlight: false },
    { positions: [...], indices: [...], highlight: true }   // 暖色：被切出的面
  ],
  edges: [x1,y1,z1, x2,y2,z2, ...],   // 扁平数值数组，每 6 个数一条线段
  polylines: [ [[x,y,z], ...], ... ], // 可选，折线自动拆成线段
  edgeColor: 0x14486f           // 可选
};
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `center` | 建议 | 缺省 `[0,0,0]`，形体偏离原点时必须给 |
| `radius` | 建议 | 包围球半径 `sqrt((w/2)²+(h/2)²+(d/2)²)`，乘 1.02 余量 |
| `views` | 否 | 只覆盖需要改的机位，例如只写 `under: [...]` |
| `meshes[].positions` | 是 | 扁平坐标数组或 Float32Array |
| `meshes[].indices` | 否 | 不给则按每 3 个点一个三角形 |
| `meshes[].highlight` | 否 | `true` → 暖色 `0xe6c49b`，专用于切面/截面 |
| `meshes[].color` / `roughness` | 否 | 覆盖默认 `0xa9cdec` / `0.62` |
| `edges` / `polylines` | 至少一个 | 手绘特征棱线；不给就没有描边 |

模板自动完成：`mergeVertices` → `computeVertexNormals` → 平滑着色 → 四盏灯 → OrbitControls → 六视角按钮 → 自动旋转 → 视距/裁剪面 → 加载失败提示。

## 2. 坐标系

- `y` 竖直向上，`x` 为主视图水平向右，`z` 为深度。
- 主视图 = 沿 `+z` 看；俯视图 = 沿 `−y` 看；左视图 = 沿 `+x` 看（相机在 `−x`）。
- 与 `volume_model.py` 的 `inside(X,Y,Z)` 保持同一坐标系，反投影才对得上。

## 3. 已验证的建模手法

### A. 高度分层扫掠（处理斜面/变截面，最常用）

不用 CSG，直接按高度把形体切成许多薄层，每层求一个平面截面，再把相邻层的对应点连成四边形：

```js
function gOf(y) {           // 该高度处被削去的左边界 x
  if (y <= ZB) return -R;   // 完整圆
  if (y <= ZT) return X0;   // 竖直台阶
  if (y <= ZS) return X0 + (y - ZT)/(ZS - ZT)*(-R - X0);  // 斜面
  return -R;
}
const p = Math.acos(clamp(g/R, -1, 1));   // 弓形截面半角
// 圆周角从 -p 扫到 +p：点 (R cos a, y, R sin a)
// 弦面：平面 x = g，端点 z = ±R sin(p)
```

要点：
- **斜面区间必须细分**（示例用 26 层）。只取上下两层会让相邻面法线差过大，出现折痕或假棱线。
- 圆周分段 `N = 128` 足够；太少圆弧会明显多边形化。
- 每层除了弧面，还要补**弦面**，否则切面是空的。
- 端面用扇形三角形 `cap(y, phiFrom, phiTo)` 封口，注意方向。

完整可运行实现见 `assets/model_example.js`（第 6 题：斜面台阶 + 通槽，7 块 `hull` 拼合，已通过体积与反投影校验）。
方法 A 属于"工具包表达不了"时的手写退路：圆柱被一族的斜面依次削短、且削切边界随高度变化时，
`sector` 的常量 `rIn/rOut` 表达不了这种渐变，只能按高度分层扫掠。

### A2. 圆柱/斜切用工具包怎么写

多数情形其实不用分层。**竖直轴圆柱被平面斜切** = `sector({axis:'y', rOut:R, a0:0, a1:2π})`
再用 `hull` 与半空间求交；或者直接：

```js
// 半圆柱凸台（轴向 z，半圈 a0..a1），再被 y ≤ h 削平
const boss = sector({ axis:'z', c1:CY, c2:CZ, rIn:0, rOut:R,
                      w0:0, w1:W, a0:-Math.PI/2, a1:Math.PI/2, seg:64 });
```

只有"同一个圆柱在不同高度被不同位置削"才需要 A 的分层法。

### B. 棱柱 / 组合体

把 A 里的「弓形」换成多边形截面：每层用相同的顶点数，按 `顶点序列` 逐边连四边形。组合体拆成多个 `meshes`，各自生成；相接处的内部面可以不画（双面材质不影响观感）。

### C. 相贯线 / 截交线

对两曲面求交，沿参数密集采样交线点，既作为棱线（`polylines`）也作为相邻面片的边界。不要用直线近似，否则三视图反投影会出现折线。

### D. 特征棱线清单

手绘时只画真正存在的棱，通常是：

- 底圆 / 顶圆（或底面 / 顶面外轮廓）
- 台阶面的外弧 + 内弦
- 竖直面的四条棱
- 斜切面与柱面的交线（空间曲线，两侧各一条）
- 相贯线

自动生成棱线一律不用：`EdgesGeometry` 在顶点未合并时会把每条三角形边都画出来，得到一片网格。

## 4. 相机与光照经验值（已调好，别再试错）

| 项 | 值 | 原因 |
|---|---|---|
| FOV | 38 | 接近正轴测，透视畸变小 |
| 视距 | `4.2 × 包围球半径` | 更近会出画面，更远看不清 |
| iso | `[C0.x-0.70D, C0.y+0.35D, C0.z+0.63D]` | 左前上方 |
| under | `[C0.x-0.62D, C0.y-0.38D, C0.z+0.68D]` | **切口朝下时唯一能看清切面的机位** |
| top | `[C0.x, C0.y+D, C0.z+0.001]` | z 留微小量避免 up 向量退化 |
| 材质 | `flatShading:false`、`DoubleSide` | 平面着色会让扭曲四边形出现明暗条纹 |
| 光照 | Hemisphere 1.55 + 四盏方向光（含底部与左后补光） | 切口不会全黑 |

机位一律以**轨道中心 `C0`**（= `MODEL.center`）为基准做偏移，不要写成相对原点的绝对值 ——
工具包生成的模型不居中，用绝对值会让模型偏到画面角落（2026-11-10 修）。

## 5. 引擎加载：内联，不用 CDN

`assets/vendor/` 里存三个文件（`three.module.min.js` 675 KB、`OrbitControls.js`、
`BufferGeometryUtils.js`），`build_viewer.py` 把它们写成三对
`<script type="text/plain" id="vw-three|vw-orbit|vw-bgu">`，模板用一段加载器在运行时：

1. 把每个源的文本打成 `Blob` → `URL.createObjectURL` → 动态 `import()`；
2. 两个 addon 源码里的 `from 'three'` 在**运行时改写成 three 的 Blob URL**，
   保证三份代码共用同一个 three 实例（否则 `instanceof` 全失效）；
3. 不走 importmap —— 它无法多源兜底、必须静态声明，还要多引一次网络。

代价：HTML 从 ~25 KB 变 ~750 KB。收益：`file://` 双击即开、断网即开、首屏 0.6 s，
再也不用赌 CDN。2026-11-10 实测 `fastly.jsdelivr` 12 秒只下 9.6 KB、`cdn.jsdelivr`
连不上，而内联版探针 601 ms 起来 —— 同一台机器、同一时刻。

换 three 版本：直接覆盖 `assets/vendor/` 三个文件即可，模板不用动。

## 6. 坑清单（全部踩过）

1. `EdgesGeometry` + 未合并顶点 → 满屏三角网格。改手绘棱线。
2. `flatShading:true` + 扭曲四边形 → 明暗条纹被误认成网格线。
3. 相机太近 → 模型出画面；太远 → 小到看不清。用 `radius*4.2`。
4. 切口朝下的形体，标准右前上方完全看不到切口，用户会以为模型做错 → 必给「仰视」按钮，并在标签里写明。
5. 斜切面与主体同色 → 被误认为一片斜插的圆盘 → `highlight: true` 标暖色。
6. 象限/方位搞反，被切掉的一侧朝向相机后方 → 先用 `raycast_preview.py` 验证机位再生成页面。
7. 浏览器截图偶发 `display surface not available` → 用离线光线投射自查，不要反复刷新截图。
8. 引 CDN 就要赌网络（2026-11-10 实测 jsdelivr 两个域名一个 12 s 只下 9.6 KB、一个连不上）→ 引擎一律内联，见第 5 节。
9. 反投影对不上时改渲染去「凑」→ 永远先改几何假设，渲染框架不动。

## 7. 验证闭环

`measure.py`（量图）→ `model.js`（`__KIT` 声明几何）→ `pipeline.py` 五步串起来：
`build_viewer`（注入 + 模块语法检查）→ `check_mesh`（体积/缺面/绕向/退化面）→
`project_mesh --auto-calib`（反投影叠回原图）→ `raycast_preview`（机位）→ `shot`（实拍 + DOM 探针）。

单步调试也可以独立跑。`verify_projection.py` 是"两边各自拉伸后比"，整体偏移会被抵消，
**已被 `project_mesh.py` 取代**，只在需要看并排对照图时用。

体积自检是唯一能抓住"半空间写反/拆不彻底"的手段 —— `--expect` 必须按公式自己算（长方体 + 圆柱 − 孔 − 槽），
误差应在 1% 内（曲面用多边形逼近时 0.05% 量级的残差属正常）。

## 8. 模式 A：视觉外壳自动重建（`auto_reconstruct.py`）

### 原理

体素属于形体，当且仅当三个投影都允许它：

```
V(x,y,z) = F(x,y) AND T(x,z) AND L(z,y)
```

F/T/L 是 `inspect_views.py` 产出的二值实心掩码（`views.npz`）。这样求出的 V 是**满足三视图的最大形体**，不需要人工推理、不需要写 `inside()`、不需要写 `model.js`。

- 坐标统一：x/z 取 `[-1,1]`，y 取 `[0,H]`，`H = 2*ny/nx`（由主视图原始宽高比定），保证长对正、高平齐。
- **手性自动择优**：俯视图与左视图的 z 方向各有 2 种可能，共 4 组合；取三视图投影吻合度最高者。实测正确解为 `top_z_flip=False, left_z_flip=False`。
- 吻合度 = `投影面积 / 输入实心面积`（视觉外壳投影必然 ⊆ 输入）。

### 掩码预处理（决定成败）

1. `inspect_views.py` 保留所有主要连通块，滤掉题号文字碎点。
2. **形态学闭运算 n=2**：视图内部的实线棱、中心线会在掩码里留下贯通到边界的白缝，`fill_holes` 抓不到（它与图外白区连通）。闭运算把 ≤2px 的缝填平；漏掉会把模型切成四块，还会把手性判别带偏。
3. `fill_holes` 再补封闭小洞。

实测效果：平均吻合度 0.9596 → **0.9945**，面片 993 → 446，模型从「裂成四块」变连续。

### 网格生成

- **贪心合并**：6 个面方向分别扫描暴露面，行内连续段合并，跨行位置相同的段继续合并。
- **共享角点**：角点 `(i,j,k)` 只存一次，所有共享该角点的面片复用同一顶点与法线。
- **平滑法线**：对每个角点，用 8 邻域实心体素的质心偏移求外法线（等价于隐式场梯度），圆柱面不会呈现方块感；无需 scikit-image。
- **紧凑序列化**：坐标保留 5 位、法线 4 位，用 `json.dumps(separators=(',',':'))`。

同一道题的体积优化轨迹：

| 阶段 | 四边形 | 顶点 | HTML |
|---|---|---|---|
| 初版（每面片独立顶点 + `repr`） | 10824 | 129888 | 4891.7 KB |
| 共享顶点 + 紧凑序列化 | 1241 | 1826 | 121.0 KB |
| 跨行合并 + 填缝后 | 446 | 620 | **45.7 KB** |

### 模板侧的配套改动

`MODEL.meshes[].normals` 新增字段：长度等于 `positions` 时，模板跳过 `mergeVertices` 与 `computeVertexNormals`，直接用外部法线。自动网格的顶点是刻意共享的，合并会破坏法线。普通参数化模型不带 `normals`，仍走原路径，互不影响。

### 局限

- 视觉外壳会填满虚线表示的内部孔/槽，这类题必须走模式 B。
- 快速模式 `edges: []`，没有特征棱线，只有着色面。
- 三视图描边线宽、扫描比例误差会让吻合度略低于 1；0.98 左右属正常。
- **高吻合度不能证明方向正确**：三张掩码被同时转置 90° 时依旧自洽。所以 `compare.png` 上排固定贴原始裁剪图，用肉眼兜底。

## 9. 绕向与定向（2026-11-10 第 3 题踩到）

**症状**：页面看起来正常，但整片明暗发闷、没有立体感；换成 `MeshStandardMaterial` + 强光也不对劲。原因不是光照，是三角形绕向反了。

**为什么看不出来**：模板材质是 `THREE.DoubleSide`，背面照样渲染，所以几何不缺角、不出洞。但 GPU 对背面片元会把法线乘 −1，于是明暗整个反过来——表面看起来"糊"而不是"错"。

**怎么抓**：算有符号体积 `V = Σ a·(b×c)/6`。闭合网格若所有面朝外，`V > 0` 且等于解析体积；若 `V < 0`，整体朝内；若 `|V|` 对不上解析值，说明缺面或面片重复。

```bash
node "<skill>/scripts/check_mesh.js" --model _ai_work/model.js --expect 4.8625
```

三项都要过：`绕向异常 0`（逐面几何法线 · 顶点法线同向）、`有符号体积` 与解析值相对误差 < 1%、`退化面 0`。

**两种朝内，修法不同**：

| 情形 | 判断 | 修法 |
|---|---|---|
| 逐面不一致（部分反） | `绕向异常 > 0` | 按 `dot(几何法线, 顶点法线) < 0` 交换三角形第 2、3 个索引 |
| 整体朝内（全部一致但都朝里） | `绕向异常 = 0` 但 `体积 < 0` | 全部三角形翻向 + 顶点法线取反 |

模板里已内置这两层自愈（`_vwRepairWinding` 与全局定向 IIFE），但**模型片段自己也要修**——否则 `check_mesh` 永远报错，而且一旦有人把材质改成 `FrontSide`，整块模型会消失。

**顺带一条**：分片建模（圆柱侧面 + 端盖分别采样）在接缝处顶点不焊接，`check_mesh` 会报成百上千条"未共用边"，这是正常的，默认只提示；`--strict` 才当失败。

## 10. 机位要跟着孔走

模板默认 `iso` 在右前上方（`[-0.70D, +0.35D, +0.63D]`）。这是通用美观机位，但**不等于能看进孔**。

第 3 题的孔开在圆柱正面偏左（x 从 −0.68R 到 0.87R），从默认机位看，左侧圆柱壁正好挡住视线，页面上只能看到一道浅色缝，用户会以为没开孔。改成右前方中等高度后，一眼就能看穿：

```js
const MODEL = {
  ...
  views: {
    iso:   [ D * 0.63, H / 2 + D * 0.21,  D * 0.92],
    under: [ D * 0.58, H / 2 - D * 0.48,  D * 0.83]
  },
```

判定方法：孔所在的 x 区间若偏 +x，机位 x 也要为正（从孔那一侧看进去），高度取孔中线附近——太高会被孔顶挡、太低会被孔底挡。选之前用 `raycast_preview.py` 打四张候选机位对比，别在浏览器里盲试。

## 11. 解析分片建模：把 CSG 实体切成四边形片（2026-11-10 第 4 题）

遇到「圆柱挖孔 / 圆柱上立凸台 / 孔中穿孔」这类曲面体，**不要**用体素+贪心网格（会变成梯田），也不要手写零散面片（容易缺面、绕向乱）。正确做法是先做一次布尔差的**面片清单**，每一片的边界都必须是某条解析交线，然后每片只用一张参数网格铺出来。

### 10.1 先列清单

对 `(A ∪ B) \ (C ∪ D)` 这类形体，逐条写出「哪张曲面、被谁切、边界是什么曲线」：

| 面 | 参数 | 边界 |
|---|---|---|
| 筒外圆面上半 | (ψ, u) 绕竖直轴极坐标 | 内圈 = 凸台足迹圆，外圈 = 矩形边界 |
| 筒外圆面下半 | 同上 | 内圈 = 竖孔足迹圆 |
| 两端端面 | (φ, r) 环形 | 内孔圆、外圆 |
| 凸台顶面 | (φ, r) 环形 | 竖孔口、凸台外圆 |
| 凸台侧面 | (φ, t) | 底边 = ①相贯线，顶边 = 圆 |
| 竖孔孔壁 | (φ, t) 上/下两带 | 内孔交线、筒底出口 |
| 内孔孔壁 | (ψ, t) 左/右两带 | 竖孔交线、端面内圆 |

清单齐了，缺面的风险基本为零——体积自检就是最后一道保险。

### 10.2 三个反复用到的技巧

**① 矩形挖同心圆盘 → 同心极坐标环带。**
筒外圆面在水平面的投影是矩形，被竖直凸台挖掉的是一个圆盘。用「以竖直轴为极点的环带」参数化：内圈半径固定（足迹圆），外圈是该方向到矩形边界的距离 `boxR(ψ)`。

```js
function boxR(psi) {
  const c = Math.cos(psi), s = Math.sin(psi);
  let t = Infinity;
  if (c >  1e-9) t = Math.min(t, ( L - X0) / c);
  if (c < -1e-9) t = Math.min(t, (-L - X0) / c);
  if (s >  1e-9) t = Math.min(t,  R / s);
  if (s < -1e-9) t = Math.min(t, -R / s);
  return t;
}
```

两个必须做的细节：
- **把矩形四个角的角度插进 ψ 采样**（`atan2(±R, ±L-X0)`），否则外边界会走弦、把角切掉；
- **径向用二次分布向外缘加密** `r = rIn + (rOut-rIn)(1-(1-u)²)`。筒面在 `z=±R` 处切线竖直，线性分布会让最外一圈跨出 0.3 个单位的 y 跳变，截面上出现一条明显的硬带。

**② 波底带：一条边是相贯线的侧面。**
凸台侧面的底边是两圆柱相贯线 `y = sqrt(R² - r²sin²θ)`，顶边是水平圆。直接按 `(θ, t)` 铺，`y` 在每条 θ 上从相贯线线性过渡到顶面即可——不需要裁剪，也不需要求交。

**③ 两带法：孔中穿孔。**
竖孔穿过水平内孔时，孔壁被切掉一段。**不要**去做"区间数量随角度变化"的拓扑跟踪。把被切的那条带拆成「上带」「下带」各铺一片：

```js
// 上带：从内孔交线 yl 到顶面；下带：从筒底出口 yb 到 -yl
const yl = Math.sqrt(Math.max(0, RB*RB - z*z));   // z = RHOLE*sin(φ)
```

在 `|z| > RB` 处 `yl = 0`，两条带的边界重合于 `y=0`，天然闭合、没有裂缝。代价只是那里有一条重合的接缝（同一张曲面，看不见）。

### 10.3 验证顺序

1. `check_mesh.js`：有符号体积 vs 解析体积/Richardson 外推体素值（本题 7.0725 vs 7.0753，差 0.05%）；`绕向异常 0`；边界边只应出现在分片接缝。
2. `project_mesh.py`：把网格投回**原图像素坐标**叠加。这一步能抓到体积检查抓不到的错误——某片镜像、某条相贯线位置偏了，体积几乎不变，但叠加图一眼就看出来。

标定值怎么量：在原图上取筒的外轮廓（左右两条竖边的中心线距离 = 2L·S）和轴线位置，即可解出 `S`、`OX`、`OZ`；俯视/左视用同一条轴线得 `OY`、`OLX`。误差控制在 1 px 内，叠加图上红线应压在描边中线上。

### 10.4 本题（第 4 题）的参数

```
R=1  RB=0.342  L=1.371  X0=0.541  RBOSS=0.830  HTOP=1.445  RHOLE=0.522
```

`X0 + RBOSS = L` —— 凸台与右端面相切，这是本题最容易看错的一处：端面不是完整圆环，凸台在端面上只留下一条切线（面积为零），端面仍是完整环形。渲染出来会看到一个尖角"刀口"，那是正确的。
